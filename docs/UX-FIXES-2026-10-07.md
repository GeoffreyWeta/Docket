# Interaction UX fixes

The shared app and demo frontend now preserves editing context and handles invalid input explicitly. Changes are local; this work did not deploy the hosted demo.

## Implemented

- Preserve new and edited tender drafts through reload, navigation, and interrupted sessions, with visible local save/recovery feedback.
- Keep bid and evaluation-note drafts separate for each account and API backend. Older unscoped bid drafts are deliberately not restored because their owner cannot be established safely.
- Batch local draft writes and flush the latest edit on blur, hiding, page exit, and component unmount.
- Preserve amount text exactly as typed. Reject fractions, negative values, malformed grouping, and unsafe totals with actionable guidance. The backend also rejects fractional prices instead of truncating them. This release supports whole naira amounts; it does not introduce decimal accounting or multi-currency support.
- Preserve typing focus and cursor selection during ordinary background refresh.
- Refresh Finance when the shared workspace refreshes. Keep existing figures visible during failures and offer retry.
- Persist Finance tab, year and spend dimension in the URL. Persist supplier portal tabs as well.
- Reset the actual desktop scroll pane on new navigation and restore its position on Back.
- Wrap vendor-chip metadata and long document names on narrow screens; show complete line totals instead of ellipsis.
- Keep form checklists in a stable order during editing.
- Show server save feedback and retry for evaluation notes; keep local recovery copies and serialize score/note writes per bid.
- Separate real/demo authentication storage and respond to account/session changes in other tabs.
- Report offline password-recovery failures instead of falsely reporting that an email is on its way. Associate its email label correctly and prevent duplicate submissions.
- Use independent title/action buttons in clickable lists, avoiding nested interactive roles.
- Provide keyboard navigation, selected tab stops and associated panels for tender, finance, and supplier tabs. Keep compliance export outside the tender tablist.
- Add a standard confirmation alternative to press-and-hold, plus Escape/focus handling for the getting-started guide.
- Add page-level render recovery and bounded network requests. Slow writes are not blindly retried.
- Use the workspace zone for new closing dates and preserve an existing closing timestamp when unrelated fields are edited.
- Improve amber figure contrast and muted landing-preview text contrast.
- Load supplier, finance and administration code on demand. Initial JavaScript decreased from 1,117 KB to approximately 961 KB raw, and from 322 KB to approximately 281 KB gzip. More splitting is still possible.
- Correct misleading RFI copy to describe the process currently supported. A dedicated information-only RFI lifecycle is still a separate feature.

## Validation

- Production frontend build succeeds; its remaining large-chunk warning is recorded rather than suppressed.
- 23 browser UX regression checks passed, covering recovery, privacy, numeric entry, mobile overflow, navigation/Back, finance freshness/view persistence, offline recovery, and editing during refresh.
- 16 amount/time-zone checks passed, including daylight-saving conversions and rejection of unsafe numeric representations.
- Backend amount-validation tests pass, including rejection of fractional/negative/non-finite values.
- All 217 procurement lifecycle checks pass after the backend validation changes.
- Django system check and Git whitespace check pass.

Run browser checks against a separate local seeded database, not an existing business workspace:

1. Set `DATABASE_URL` to a disposable SQLite database.
2. Run `python manage.py migrate` and `python manage.py seed_demo` from `backend`.
3. Build the frontend, then start that backend with `DEBUG=1` on `127.0.0.1:8765`.
4. From `frontend`, run `npm run test:ux`. If necessary, install its browser once with `npx playwright install chromium`.
5. From `backend`, run `python test_ux_amounts.py`.

Restart the local Django process after rebuilding the production bundle: its cached template can otherwise refer to the previous content-hashed asset. The existing development Vite server is the appropriate route for continuous hot reload.

## Remaining work from the broader audit

This interaction release does not implement server-side pagination, an asynchronous email outbox, MFA recovery codes, complete multi-currency accounting, an information-only RFI lifecycle, SSO, upload malware scanning, or a production deployment. A full screen-reader/physical-device review and complete visual contrast/heading audit also remain. The existing Vite build-tool dependency advisories need a separate compatible upgrade; no automatic major upgrade was applied during the UX fixes.
